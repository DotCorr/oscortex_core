oscortex_core M14 -- a read-only FAT16 filesystem.

This file is TWO clusters long and its two clusters are not adjacent:
the first is cluster 2 and the second is cluster 100. A `cat` that read
forward from the first cluster instead of following the FAT would print
the volume's background pattern here instead of the rest of this text.

The kernel that prints this has no writes, no subdirectories, no long
filenames and no timestamps. It has a boot sector it validated, a FAT it
walks, a root directory it enumerates and files it reads by name. That is
the whole of it, and docs/known-gaps.md says so at greater length.

Below this line is padding, and it is here for one arithmetical reason:
a cluster on this volume is 1024 bytes, and a file has to be longer than
one cluster before its chain has a second link to follow. Everything up
to here is 800-odd bytes, which would have fitted in cluster 2 alone.
